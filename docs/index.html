Por qué ahora

Esto siempre pasó. Pero pasaba a ritmo humano.

Antes

Las decisiones técnicas se tomaban en reuniones, PRs largos y hilos de Slack. Pocas por semana. Alguien se acordaba, y con eso alcanzaba.

Ahora

Cada persona toma decenas de decisiones por día conversando con su asistente. Qué librería, qué patrón, qué se descartó. El razonamiento suele ser bueno. Y es privado.

El agravante

La IA de cada uno no conoce lo que decidió la IA de los demás. Así que se contradicen entre sí, con excelentes argumentos las dos.

El volumen de decisiones se multiplicó. La memoria del equipo siguió siendo la misma. Los ADR formales no escalan a este ritmo: nadie va a escribir treinta documentos por día. Hay que capturar donde la decisión nace: en la sesión.

porque src/api/payments.ts

● Usar zod para validación de requests  2026-09-01 · Lu
  Se adopta zod como librería de validación de body en la API,
  infiriendo el tipo PaymentRequest directamente del schema.
  Por qué: infiere tipos TS desde el schema evitando duplicar tipo y
  schema; el equipo lo va a necesitar igual para validar config de
  entorno y respuestas de Stripe; sus errores son legibles para el front.
  Descartado: yup: inferencia de tipos más débil | JSON Schema de
  Fastify (ajv): dos fuentes de verdad (schema y tipo)
  decisions/2026-09-01-usar-zod-para-validacion-de-requests.md · src/api/**

● Idempotencia de pagos vía header Idempotency-Key + Redis  2026-09-01 · Lu
  POST /payments requiere un header Idempotency-Key (UUID).
  Por qué: evitar doble cobro por doble click o reintentos. Redis y no
  Postgres porque ya está en el stack, el TTL es nativo y no ensucia la
  tabla de pagos. 24h replica la convención de Stripe.
  Descartado: tabla en Postgres: expiración manual y basura de reintentos
  decisions/2026-09-01-idempotencia-de-pagos-via-header-idempotency-key-redis.md

● Representar amount en centavos como entero  2026-09-01 · Lu
  Por qué: los floats de JavaScript no representan exactamente los
  decimales (0.1 + 0.2 !== 0.3); en pagos eso genera diferencias de un
  centavo en conciliaciones. Convención de Stripe y Mercado Pago.
  Descartado: Decimal (decimal.js / numeric): dependencia extra, string en JSON
  decisions/2026-09-01-representar-amount-en-centavos-como-entero.md

Probalo

Sesenta segundos, un repo de prueba y una sesión grabada.

Cloná el repo y corré el demo. Crea un repo de prueba, reproduce la sesión del martes y pregunta porque why.

En tu propio repo: npx --yes porque-cli init. Crea decisions/, el bloque en CLAUDE.md y el hook de Claude Code. Después trabajás como siempre.

Sumá el workflow de GitHub Actions del repo para que cada PR muestre las decisiones que toca.
